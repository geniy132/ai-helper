# AI-помощник для B2B товарных описаний (КИПиА)

[![CI Pipeline](https://github.com/geniy132/ai-helper/actions/workflows/ci.yml/badge.svg)](https://github.com/geniy132/ai-helper/actions)
![Python](https://img.shields.io/badge/Python-3.12-blue.svg)

![Ollama](https://img.shields.io/badge/Ollama-Qwen%202.5%20Coder-black.svg)
![License](https://img.shields.io/badge/License-MIT-green.svg)

Сервис автоматизированной оцифровки технических паспортов и генерации карточек товаров для B2B интернет-магазина промышленного оборудования, контрольно-измерительных приборов и автоматики (КИПиА).

Сервис принимает технические характеристики прибора в формате JSON или через веб-форму, отправляет структурированный запрос в локальную нейросеть **Ollama (Qwen)**, верифицирует данные программным защитным контуром против галлюцинаций и генерирует готовую карточку с SEO-оптимизацией и commercial-блоком для отдела продаж.

<a id="architecture"></a>
## 🏛 Архитектура и инженерные решения

Система построена на принципах **Clean Architecture** и строгого разделения слоев (`src`-layout):

```text
ai_helper/
├── data/
│   ├── samples.json                 # Эталонные наборы данных оборудования Союз-Прибор
│   └── texts.json                   # Изолированные промпты, тексты и словари аудита
├── src/
│   ├── config.py                    # Типобезопасная конфигурация через .env
│   ├── constants.py                 # Централизованные константы и лимиты ТЗ
│   ├── texts.py                     # Загрузчик текстов и шаблонов из texts.json
│   ├── models/
│   │   └── product.py               # Pydantic v2 схемы данных с авто-coercion
│   ├── prompts/
│   │   └── templates.py             # Системные и пользовательские промпты
│   ├── services/
│   │   ├── generator.py             # Оркестратор генерации карточек
│   │   ├── anti_hallucination.py    # Двухуровневый верификатор ТТХ (Hallucination Guard)
│   │   └── providers/               # Провайдеры генерации (паттерн Strategy)
│   │       ├── base.py              # Базовый абстрактный контракт
│   │       ├── ollama_provider.py   # Нативная асинхронная интеграция с Ollama через httpx
│   │       └── mock_provider.py     # Детерминированный офлайн-движок для CI/CD тестов
│   └── web/
│       ├── app.py                   # Запуск FastAPI, CORS и раздача статики
│       ├── dependencies.py          # Слой внедрения зависимостей (DI) и Security Guard
│       ├── api/
│       │   └── v1/
│       │       ├── router.py        # Аггрегатор маршрутов API v1
│       │       └── endpoints/
│       │           ├── generate.py  # Типизированный эндпоинт генерации
│       │           ├── health.py    # Мониторинг состояния сервиса
│       │           └── presets.py   # Отдача каталога образцов оборудования
│       └── static/                  # Реактивный веб-интерфейс (TailwindCSS, Vanilla JS)
├── tests/                           # Модульные и интеграционные тесты (Pytest)
├── cli.py                           # CLI-утилита для пакетной обработки
├── run.py                           # Скрипт быстрого запуска
├── pyproject.toml                   # Единый стандарт сборки и настроек инструментов (PEP 518/621)
├── requirements.txt                 # Зависимости с краткими комментариями
├── Dockerfile & docker-compose      # Контейнеризация приложения
└── README.md
```

### Ключевые решения:
1. **Локальный AI-движок на базе Ollama (Qwen 2.5 Coder)**:
   - Сервис использует открытую модель **Qwen 2.5 Coder**, развернутую локально на GPU через Ollama.
   - Взаимодействие реализовано напрямую через легковесный асинхронный `httpx` к нативному эндпоинту `/api/chat` со строгой JSON-схемой, без лишних сторонних библиотек.
   - Для работы в CI/CD и автономного запуска без активного демона Ollama предусмотрен детерминированный `MockProvider`.
2. **Модульная архитектура API v1 и безопасность**:
   - Маршрутизация разделена на независимые контроллеры в `src/web/api/v1/endpoints/`.
   - Поддерживается версионирование (`/api/v1/generate` и `/api/generate`).
   - Реализован Security Guard в `dependencies.py`: проверка заголовка `X-API-Key` при включении авторизации в `.env`.
3. **Изоляция контента и промптов (`data/texts.json`)**:
   - Тексты промптов, маркетинговые шаблоны, сообщения аудита и формулировки вынесены в JSON, что изолирует кодовую базу от правок контента.
4. **Типобезопасность на Pydantic v2**:
   - Строгая валидация входящих данных и предвалидаторы (coercion), приводящие вариативные ответы моделей (списки, вложенные объекты) к надежным строковым типам.
5. **Двухуровневая защита от галлюцинаций (`AntiHallucinationGuard`)**:
   - *Промпт-уровень:* строгий системный промпт с *Closed-World Assumption* (модели запрещено выдумывать параметры при их отсутствии в паспорте).
   - *Код-уровень:* программный пост-валидатор, извлекающий все числовые характеристики и единицы измерений из сгенерированной карточки и сверяющий их с сырыми данными паспорта. Все неподтвержденные параметры маркируются как требующие уточнения.
6. **Контроль жестких SEO-метрик**:
   - SEO-заголовок: авто-тримминг по границам слов до 70 символов.
   - SEO-описание: интеллектуальная подгонка под диапазон 800–1200 символов.

<a id="quickstart"></a>
## 🛠 Быстрый запуск и инструкция

### Шаг 1: Запуск модели в Ollama

1. **Запустите фоновый сервис Ollama** (в окне терминала):
   ```powershell
   ollama serve
   ```
   *Сервис поднимет локальный REST API на `http://localhost:11434`.*

2. **Проверьте наличие модели:**
   ```powershell
   ollama list
   ```
   *Если модель еще не скачана:*
   ```powershell
   ollama pull qwen2.5-coder:1.5b
   ```

---

### Шаг 2: Установка и запуск веб-сервера проекта

1. **Клонирование репозитория:**
   ```powershell
   git clone https://github.com/geniy132/ai-helper.git
   cd ai-helper
   ```

2. **Создание и активация виртуального окружения (Python 3.10+):**
   ```powershell
   python -m venv venv
   .\venv\Scripts\Activate.ps1
   ```

3. **Установка зависимостей:**
   ```powershell
   pip install -r requirements.txt
   ```

4. **Запуск веб-сервера:**
   ```powershell
   python run.py
   ```
   *(Или через Uvicorn с автоперезагрузкой: `uvicorn src.web.app:app --host 127.0.0.1 --port 8000 --reload`)*

5. **Откройте приложение в браузере:**
   Перейдите по адресу: **[http://localhost:8000](http://localhost:8000)**  
   Интерактивная документация Swagger доступна по адресу: **[http://localhost:8000/docs](http://localhost:8000/docs)**

---

### Запуск в Docker

Для изолированного запуска доступен Dockerfile и docker-compose:
```powershell
docker-compose up --build
```
*Сервис будет доступен по адресу `http://localhost:8000`.*

### Запуск тестов

Комплекс из 15 тестов проверяет модели данных, обработку пропусков, защиту от галлюцинаций, права доступа и API:
```powershell
pytest -v
```

## 💻 Использование CLI

Для пакетной оцифровки оборудования и интеграции в пайплайны предусмотрена консольная утилита `cli.py`:

```bash
# Генерация для первого пресета в формате Markdown
python cli.py --preset 0 --format markdown

# Генерация карточки GSM-модема в чистый JSON
python cli.py --preset 1 --format json

# Генерация для прибора с сохранением в файл
python cli.py --preset 2 --format markdown --output result_incomplete.md

# Генерация по произвольному входному JSON-файлу
python cli.py --input path/to/product.json --format text
```

<a id="prompts"></a>
## 🎯 Промпт-инжиниринг и защита от галлюцинаций

### 1. Архитектура системного промпта
Системный промпт (загружаемый из `data/texts.json` через `src/prompts/templates.py`) задает строгую ролевую модель:
- **Роль:** Ведущий технический копирайтер и эксперт по промышленному оборудованию КИПиА.
- **Closed-World Constraint:** Строгий запрет на экстраполяцию технических цифр. Если модель не находит параметр в исходных данных — параметр помечается как «данных нет».
- **Инструкции по форматированию:** Жесткие диапазоны длины (заголовок до 70 симв., описание 800–1200 симв.) и генерация валидного JSON.

### 2. Защитный контур `AntiHallucinationGuard`
Даже самая современная LLM способна галлюцинировать стандартные значения (например, подставлять IP65 вместо IP20 или 24 В вместо 220 В).
В проекте реализован программный верификатор `AntiHallucinationGuard`, который:
1. Извлекает числовые метрики и диапазоны из выходных характеристик.
2. Проверяет их наличие в сыром входном тексте и спецификациях.
3. Если значение выдумано, оно автоматически нейтрализуется предупреждением `(требует уточнения: нет в паспорте)`.
4. Инспектирует входной объект на наличие критических параметров КИПиА (питание, интерфейсы, защита, диапазон) и формирует отчет о пропущенных полях.
