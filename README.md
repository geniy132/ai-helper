# AI-помощник для подготовки товарных описаний (B2B КИПиА)

[![CI Pipeline](https://github.com/geniy132/souz-pribor-ai-helper/actions/workflows/ci.yml/badge.svg)](https://github.com/geniy132/souz-pribor-ai-helper/actions)
![Python](https://img.shields.io/badge/Python-3.12-blue.svg)
![FastAPI](https://img.shields.io/badge/FastAPI-0.115+-009688.svg)
![Pydantic](https://img.shields.io/badge/Pydantic-v2-E92063.svg)
![License](https://img.shields.io/badge/License-MIT-green.svg)

Прототип сервиса автоматизированной подготовки черновиков карточек товаров для B2B интернет-магазина промышленного оборудования, датчиков и приборов КИПиА компании **«Союз-Прибор»**.

Сервис принимает технические данные о приборе в формате JSON или через веб-форму, отправляет структурированный запрос в LLM, верифицирует данные защитным слоем против галлюцинаций и генерирует готовую карточку с SEO-оптимизацией и commercial-блоком для отдела продаж.

## 🏛 Архитектура и принятые инженерные решения

Система построена на принципах **Clean Architecture** и разделения ответственности (Separation of Concerns):

```
ai_helper/
├── data/
│   └── samples.json             # Эталонные датасеты из YML-каталога «Союз-Прибор»
├── docs/
│   └── test_task.pdf            # Исходное техническое задание
├── src/
│   ├── config.py                # Типобезопасная конфигурация через .env
│   ├── models/
│   │   └── product.py           # Pydantic v2 схемы (ProductInput, ProductCardOutput)
│   ├── prompts/
│   │   └── templates.py         # Системные и пользовательские промпты с zero-shot CoT
│   ├── services/
│   │   ├── generator.py         # Оркестратор генерации
│   │   ├── anti_hallucination.py# Двухуровневый верификатор ТТХ (Hallucination Guard)
│   │   └── providers/           # Паттерн Strategy для подключения LLM
│   │       ├── base.py          # Базовый абстрактный провайдер
│   │       ├── mock_provider.py # Детерминированный офлайн-движок (работает без API-ключей)
│   │       ├── google_provider.py# Google Gemini API
│   │       └── openai_provider.py# OpenAI API (GPT-4o-mini, Groq, Ollama)
│   └── web/
│       ├── app.py               # Асинхронный REST API (FastAPI)
│       └── static/              # Легковесный реактивный UI (TailwindCSS, Vanilla JS)
├── tests/                       # 11 модульных и интеграционных тестов (Pytest)
├── cli.py                       # CLI-утилита терминального запуска
├── Dockerfile & docker-compose  # Контейнеризация
└── README.md
```

### Принятые архитектурные решения:
1. **Паттерн Provider Strategy & Factory**:
   - Поддерживает **Google Gemini**, **OpenAI** и встроенный **Mock / Offline Provider**.
   - Позволяет ревьюеру запустить и протестировать 100% функционала UI и API локально **без необходимости заводить платные API-ключи**.
2. **Pydantic v2 Schema Enforcement**:
   - Строгая типизация входных и выходных параметров.
   - Автоматическая валидация пустых полей с понятными человекочитаемыми ошибками HTTP 422.
3. **Двухуровневая защита от галлюцинаций (Anti-Hallucination Guard)**:
   - *Уровень 1 (Prompt):* Strict System Prompt с закрытым миром (closed-world assumption) и явным указанием писать «данных нет» вместо выдумывания.
   - *Уровень 2 (Code Guard):* Программный аудит `AntiHallucinationGuard`, который сверяет все числовые и инженерные параметры в `key_specs` с исходным текстом. Если значение отсутствует в паспорте — оно помечается как требующее уточнения.
4. **Контроль жестких SEO-метрик**:
   - SEO-заголовок: автоматический тримминг по границам слов до 70 символов.
   - SEO-описание: контроль диапазона строго 800–1200 символов.

## 🚀 Ключевые возможности

- ⚡ **Два режима ввода:** Интуитивная веб-форма и сырой JSON-редактор с форматированием.
- 📦 **Готовые пресеты из каталога «Союз-Прибор»:**
  1. `Модуль дискретного ввода/вывода ОВЕН МК110-224.8Д.4Р [М01]` (сложный модуль промышленной автоматизации RS-485).
  2. `GSM/GPRS-модем ОВЕН ПМ01-24.АВ` (устройство телеметрии и беспроводной связи).
  3. `Манометр ДМ 05063 (Неполные данные)` (демонстрация работы детектора пропусков и предупреждений для менеджера).
- 📋 **Копирование в 1 клик в 4 форматах:**
  - Наглядная интерактивная карточка (таблица ТТХ, теги запросов, commercial-блок).
  - Чистый GitHub Flavored Markdown (`.md`).
  - Текстовый вариант для CMS (`.txt`).
  - Строгий структурированный JSON.
- ⚠️ **Детекция неполных данных:** Вывод предупреждающих бейджей контент-менеджеру (пропущен производитель, нет диапазона измерений, интерфейса и т.д.).

## 🛠 Быстрый запуск

### Вариант 1: Локальный запуск (Python 3.10+)

```bash
# 1. Клонирование репозитория
git clone https://github.com/geniy132/souz-pribor-ai-helper.git
cd souz-pribor-ai-helper

# 2. Создание и активация виртуального окружения
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

# 3. Установка зависимостей
pip install -r requirements.txt

# 4. (Опционально) Настройка API-ключей
cp .env.example .env
# Отредактируйте .env при необходимости использовать реальный Gemini или OpenAI.
# По умолчанию включен LLM_PROVIDER=mock (ключи не требуются!)

# 5. Запуск веб-сервиса
uvicorn src.web.app:app --reload --port 8000
```
Откройте браузер по адресу: **`http://localhost:8000`**

### Вариант 2: Запуск в Docker

```bash
docker-compose up --build
```
Сервис доступен по адресу: **`http://localhost:8000`**

### Запуск тестов

```bash
pytest -v
```
Все 11 тестов проверяют модели, валидаторы, детектор галлюцинаций и API эндпоинты.

## 🎯 Описание промптов и защита от галлюцинаций

### 1. Архитектура системного промпта
Системный промпт (`src/prompts/templates.py`) задает строгую ролевую модель:
- **Роль:** Ведущий технический копирайтер и эксперт по промышленному оборудованию КИПиА.
- **Closed-World Constraint:** Строгий запрет на экстраполяцию технических цифр. Если модель не находит параметр в исходных данных — параметр помечается как «данных нет».
- **Инструкции по форматированию:** Жесткие диапазоны длины (заголовок до 70 симв., описание 800–1200 симв.) и генерация валидного JSON.

### 2. Защитный контур `AntiHallucinationGuard`
Даже самая современная LLM при низких температурах способна галлюцинировать стандартные значения (например, придумывать IP65 вместо IP20 или 24 В вместо 220 В).
В проекте реализован программный верификатор `AntiHallucinationGuard`, который:
1. Извлекает числовые метрики и диапазоны из выходных характеристик.
2. Проверяет их наличие в сыром входном тексте и спецификациях.
3. Если значение выдумано, оно автоматически нейтрализуется предупреждением `(требует уточнения: нет в паспорте)`.
4. Инспектирует входной объект на наличие критических параметров КИПиА (питание, интерфейсы, защита, диапазон) и выводит список замечаний для контент-менеджера.

## 🚧 Ограничения решения и план развития

### Текущие ограничения (MVP):
1. Работает с отдельными товарами (нет фоновой очереди пакетной обработки на 50 000 позиций).
2. Анализирует текстовые данные (не извлекает таблицы напрямую из PDF-чертежей и графических сканов паспортов).
3. Использует локальное хранилище без интеграции с внешней СУБД (PostgreSQL / Redis).

### План развития (Production Roadmap):
- [ ] **RAG по нормативной базе ГОСТ/ТУ:** Подключение векторной базы данных (Qdrant / Chroma) со стандартами КИПиА для автоматической проверки совместимости единиц измерений.
- [ ] **Batch Processing & Celery/Redis:** Очередь асинхронных задач для пакетного прогона каталогов YML/CSV из 100 000+ товаров.
- [ ] **Мультимодальный парсинг PDF/OCR:** Интеграция с Vision-моделями (Gemini 2.5 Flash / Claude Sonnet) для извлечения габаритных чертежей и электрических схем из сканов паспортов.
- [ ] **A/B тестирование промптов:** Сравнение конверсии карточек товаров с разными стилями commercial-блоков через аналитику B2B магазина.
